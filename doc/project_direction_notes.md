# AI Driven RPG Design Foundation

## 0. 总开发第一原则：禁止任何最小闭环思想

禁止任何最小闭环思想。不得以“先跑起来”、“先接一条最短链路”、“先做临时闭环”、“以后再回归架构”为理由，绕过已经确立或应当先确立的规则、语义、数据、运行时与验证契约。

每一次开发都必须建设最终系统的一部分。如果正确契约尚未清楚，应先澄清契约，再实现功能。临时演示、局部闭环、一次性适配、为了让某个阶段看似完成而添加的过渡结构，默认都是架构风险，不能作为项目推进方式。

当已有成熟方案存在时，后续阶段必须继承其正确契约，只能替换明确被废弃的实现部分。新阶段不能因为重置实现路线而丢弃已经成熟的运行模型。

本文档记录一个 AI 驱动传统 RPG 的基础设计方向。

本项目目标是制作一个传统 2D 俯视角开放世界 RPG，再用 AI 增强内容生成、NPC 表达、世界反馈和叙事结算。项目不是 AI 聊天客户端，也不是先做 AI 再补游戏规则。

当前设计原则：

```text
先做没有 AI 也能成立的 Godot 单机 RPG 本体。
前期不接后端数据库、不接 RAG、不接 AI。
Godot 内部必须拥有完整的表现层、规则层、场景系统、角色系统、行动系统、物品、任务、时间、战斗、经营等基础能力。
后端、RAG、AI 服务放到后期重新设计，只作为增强层接入。
AI 生成候选内容、对白、摘要、描述和叙事反馈，不直接修改世界事实。
游戏规则层决定事实，世界状态保存事实，表现层展示事实。
```

工程推进原则：

```text
不做临时最小闭环。
不为了展示效果绕过架构。
每一步都填充最终架构的一部分。
后面的系统只能依赖前面已经稳定的系统。
表现层不能直接改世界事实。
AI 不能绕过规则层。
```

当前优先方向：

```text
第一大阶段：纯 Godot 单机 RPG 本体。
第二大阶段：程序生成。
第三大阶段：AI / 后端增强层。
```

## 1. 游戏愿景

这是一个传统 2D 俯视角开放世界 RPG。

玩家扮演一个由自己定义的世界居民，在一个大而有限的世界中生活。玩家可以探索、战斗、经营、制作、种植、交易、结交 NPC、加入队伍、参与势力事件，也可以只是在世界中安静生活。

游戏没有强制主线，也没有固定结局。玩家可以自行决定目标；当玩家死亡或主动结束旅程时，游戏根据玩家经历生成结局结算。

一句话定位：

```text
一个没有强制主线、以探索和角色行动为核心的传统开放世界 RPG，并用 AI 扩展内容、NPC 表达和叙事反馈。
```

## 2. 设计支柱

### 2.1 传统 RPG 先于 AI

游戏本体必须在没有 AI 的情况下成立。

AI 用于增强：

```text
内容生成
NPC 表达
地点描述
任务候选
传闻
经历总结
结局叙事
```

AI 不替代：

```text
战斗规则
任务完成判定
奖励发放
角色成长
物品获得
世界事实写入
NPC 生死判定
```

### 2.2 玩家自由生活

玩家不是被主线推着走的主角，而是世界中的一个人。

玩家可以选择：

```text
冒险者
佣兵
商人
农场主
工匠
炼金师
旅馆老板
公会经营者
领主
流浪者
```

不同身份影响初始属性、技能倾向、装备、金币和关系。

### 2.3 探索驱动

探索是核心体验。

玩家通过移动、调查、对话、进入地点、发现资源、遭遇 NPC、触发事件来理解世界。

探索应产生真实结果：

```text
发现地点
获得物品
认识 NPC
发现任务
触发战斗
改变关系
解锁信息
改变场景状态
```

### 2.4 世界事实稳定

世界高层设定应稳定，局部内容可以生成。

```text
高层事实：作者或系统预先确定。
局部内容：程序和 AI 可以生成。
```

AI 不能随意改写高层事实。

### 2.5 行动改变世界

游戏不是靠固定剧情节点推进，而是靠玩家行动产生结果。

几乎所有非移动行为都可能改变世界：

```text
对话
调查
拾取
使用物品
战斗
交易
休息
制作
种植
经营
接受任务
加入队伍
```

## 3. 工程工作流程

工程实现分为三个大阶段：

```text
第一阶段：Godot 单机 RPG 本体
第二阶段：程序生成
第三阶段：AI / 后端增强层
```

第一阶段只使用 Godot 完成游戏本体，不接后端数据库、不接 RAG、不接 AI。目标是让传统 RPG 的表现层、规则层和核心系统先成立。

第二阶段在已有规则结构上加入程序生成，让生成内容落入已有场景、角色、物品、任务和世界状态结构中。

第三阶段再重新设计后端、数据库、RAG 和 AI 服务。AI 只作为增强层接入，不反过来决定游戏本体结构。

### 3.1 阶段 0：新项目骨架

创建全新的 Godot 项目结构。

本阶段目标：

```text
建立清晰的目录结构
区分场景、脚本、资源、数据、UI、系统、工具
为后续所有系统预留稳定位置
```

不追求可玩效果，只保证项目结构干净。

### 3.2 阶段 1：基础运行框架

建立 Godot 内部基础框架。

本阶段包含：

```text
主启动场景
全局游戏状态管理
场景加载管理
时间管理基础
输入管理
UI 根节点
调试面板入口
```

目标是让所有后续系统有统一挂载位置。

### 3.3 阶段 2：场景系统

场景是游戏的基础环境单位，因此优先实现。

本阶段包含：

```text
瓦片地图场景结构
场景元数据
场景入口 / 出口
场景坐标体系
格子占用规则
场景内对象注册
场景切换
```

目标：

```text
游戏知道当前在哪个场景。
场景知道自己有哪些格子、入口、对象和状态。
```

### 3.4 阶段 3：角色实体系统

先实现通用角色实体，再区分玩家、NPC、敌人和队友。

本阶段包含：

```text
Character 基础实体
格子位置
朝向
移动
属性容器
身份信息
阵营 / 关系占位
可交互标记
可战斗标记
```

目标：

```text
玩家和 NPC 首先都是世界里的角色实体。
```

### 3.5 阶段 4：行动系统

行动系统是规则层核心。

所有会改变世界的行为都应通过统一 Action 结构，而不是由 UI、NPC、AI 或场景节点直接改状态。

核心行动包括：

```text
MoveAction
TalkAction
InspectAction
PickUpAction
UseItemAction
AttackAction
TradeAction
RestAction
CraftAction
AcceptQuestAction
```

每个 Action 都应具有：

```text
发起者
目标
条件检查
执行结果
世界状态变化
表现反馈
```

目标：

```text
所有世界变化都经过行动系统和规则层。
```

### 3.6 阶段 5：物品和交互对象系统

在行动系统之后实现物品和交互对象。

本阶段包含：

```text
Item 定义
Inventory
装备槽
场景掉落物
可调查对象
可拾取对象
可使用对象
```

目标是让探索开始拥有可交互内容，并保持所有结果通过行动系统生效。

### 3.7 阶段 6：非 AI 对话系统

先实现传统 RPG 对话系统，不接 AI。

本阶段包含：

```text
对话资源
条件对白
选项对白
对话触发
对话结果
```

对话不能直接改世界。对话结果必须通过行动系统、规则层或事件结果生效。

### 3.8 阶段 7：任务系统

任务系统在角色、行动、物品和对话之后实现。

本阶段包含：

```text
Quest 定义
Quest State
Quest Objective
Quest Reward
Quest Source
任务接受
任务推进
任务完成
任务失败
```

任务推进必须来自行动结果、世界状态或事件触发。

### 3.9 阶段 8：时间和 NPC 日程

建立世界时间和 NPC 生活节奏。

本阶段包含：

```text
白天 / 夜晚
日期
时间推进
NPC 日程表
场景内 NPC 移动
离场后的简化结算接口
```

目标是让 NPC 像在生活，而不是一开始追求全量真实模拟。

### 3.10 阶段 9：关系系统

关系系统依赖角色、行动、对话和任务，因此放在这些系统之后。

本阶段包含：

```text
角色关系
阵营关系
好感 / 敌意
关系事件
关系对对白、任务、交易和战斗的影响
```

### 3.11 阶段 10：战旗战斗系统

战斗是核心玩法，但依赖场景格子、角色实体、属性、装备、行动系统和阵营关系，因此不能过早实现。

本阶段包含：

```text
进入战斗模式
回合系统
行动点 / 移动范围
攻击
技能
受伤 / 死亡 / 逃跑
战斗结果写回世界
```

目标是让战斗成为世界规则的一部分，而不是独立小游戏。

### 3.12 阶段 11：制作、种植、经营系统

制作、种植、经营是长期玩法路线。

建议顺序：

```text
制作
种植
经营
```

原因：

```text
制作主要依赖物品。
种植依赖物品、时间和场景。
经营依赖 NPC、交易、任务、经济和场景。
```

### 3.13 阶段 12：程序生成

程序生成在基础规则稳定后接入。

本阶段包含：

```text
场景生成
小镇生成
NPC 生成
资源分布
地牢生成
任务候选生成
```

生成结果必须落入已有结构中，不能生成例外格式。

### 3.14 阶段 13：AI / 后端增强层

AI、后端数据库、RAG 和远程服务在本阶段重新设计。

建议接入顺序：

```text
AI 生成 NPC 对白
AI 生成地点描述
AI 生成传闻
AI 辅助 NPC 记忆总结
AI 生成任务候选
AI 生成结局叙事
AI 辅助生成小镇语义
```

AI 输出进入：

```text
候选内容
建议
描述
摘要
叙事反馈
```

AI 不直接写入世界事实，不绕过行动系统和规则层。

### 3.15 工程依赖原则

```text
后面的系统只能依赖前面已经稳定的系统。
表现层不能直接修改世界事实。
AI 不能绕过行动系统和规则层。
生成内容必须落入已有数据结构。
如果某个系统需要改变前面系统的定义，应先回到架构层调整定义，再继续实现。
```

## 4. 游戏形态

### 4.1 基本规格

```text
类型：传统角色扮演 RPG
视角：2D 俯视角
地图：瓦片格子地图
角色表现：16x16 正面二头身像素小人
世界形态：大而有限的开放世界
美术气质：像素温暖小镇 + 传统 JRPG
核心体验：探索
重要玩法：战旗战斗、经营、制作、种植、社交、成长
主线：无强制主线
结局：无固定结局
节奏：安静探索为主，提供主动参与事件的入口
```

### 4.2 主要游戏模式

游戏表现层至少包含以下模式：

```text
探索模式
对话模式
战斗模式
交易模式
制作模式
种植模式
经营模式
菜单 / 管理界面
```

探索和战斗共享格子世界。探索时玩家自由移动；战斗开始后，当前场景切换为战旗规则。

## 5. 世界模型

### 5.1 世界规模

世界是一个很大的有限世界。

玩家可以自主选择出生点。玩家角色的信息主要由玩家填写，系统只规定需要填写的字段和可选范围。

### 5.2 世界内容层级

世界内容分为两层。

第一层是固定高层设定：

```text
世界观
基础历史
重要国家
重要势力
重要城市
重要地区
重要人物
魔法 / 技术水平
种族与文化边界
怪物或危险来源
```

第二层是可生成局部内容：

```text
普通小镇
野外区域
地牢
普通 NPC
地方事件
商店库存
任务候选
传闻
资源分布
```

固定高层设定负责保持世界一致性。程序生成和 AI 生成负责补充具体内容。

## 6. 场景模型

### 6.1 场景定义

场景是游戏的基础环境单位。

场景可以是：

```text
一个小镇
大城市的一部分
野外区域
地牢区域
建筑内部
战斗区域
```

场景由瓦片格子组成。玩家、NPC、物品和交互对象都存在于场景格子中。

### 6.2 场景职责

场景不仅是地图，也是规则单位。

一个场景可以包含：

```text
地形
出入口
NPC
物品
可调查对象
时间状态
危险度
归属势力
当前事件
资源点
建筑
```

场景承担探索、交互、移动、遭遇和战斗承载职责。

### 6.3 场景连续性

理想状态是连续世界。

如果连续大世界成本过高，可以采用：

```text
同一大场景内连续移动。
不同场景之间通过出入口切换。
```

## 7. 角色模型

### 7.1 玩家角色

玩家扮演一个由自己定义的世界居民。

玩家角色可包含：

```text
名字
年龄
种族
性别
出身地
身份 / 职业
性格
初始目标
初始资产
初始装备
初始关系
属性分布
技能倾向
```

不同身份会影响：

```text
属性点分布
初始技能
初始装备
初始金币
初始关系
出生点选择
```

### 7.2 NPC

NPC 是完整的世界角色，不只是对话对象。

NPC 可以拥有：

```text
身份
属性
等级
技能
装备
持有物
关系
阵营
当前位置
日程
情绪
目标
秘密
可战斗能力
可交易能力
发布任务能力
加入队伍的可能性
死亡或离开的可能性
```

NPC 可以执行：

```text
移动
工作
交易
对话
发布任务
加入队伍
战斗
隐瞒信息
改变关系
离开地区
死亡
成为敌人
影响世界事件
```

所有 NPC 理论上都可以进入战斗。NPC 可以主动挑起战斗，玩家也可以主动攻击 NPC。

### 7.3 NPC 模拟层级

NPC 生活模拟分为三层：

```text
活跃模拟：
玩家所在场景内，NPC 真实移动和响应。

半活跃模拟：
重要 NPC 或附近场景，按日程和事件简化推进。

后台模拟：
远方普通 NPC 不实时行动，只在需要时结算一段时间内发生的变化。
```

目标不是全量实时模拟，而是让玩家感到 NPC 在生活。

## 8. 行动模型

玩家通过行动改变世界。

核心行动包括：

```text
移动
对话
调查
拾取
使用物品
战斗
交易
休息
制作
种植
经营
接受任务
加入队伍
进入 / 离开场景
```

移动主要改变位置。其他行动通常会影响角色状态、物品、关系、任务、场景或世界事件。

## 9. 玩法系统

### 9.1 探索系统

探索对象包括：

```text
城镇
野外
地牢
建筑
道路
资源点
遗迹
危险区域
隐藏地点
NPC 活动区域
```

探索是接触其他系统的入口：玩家通过探索发现 NPC、任务、资源、敌人、地点、事件和经营机会。

### 9.2 任务系统

任务主要来自 NPC。

冒险者协会、告示板、公会、商店委托等，本质上也是 NPC 或组织发布任务的媒介。

任务可以是：

```text
请求
委托
交易
威胁
契约
约定
悬赏
调查
护送
制作订单
经营需求
势力目标
```

任务完成应产生收益，也可能产生后果。

任务结果可能影响：

```text
金钱
物品
经验
关系
声望
阵营
地点状态
后续任务
世界事件
```

### 9.3 战旗战斗系统

战斗是核心玩法，形式为战旗。

战斗可以由多种方式触发：

```text
玩家主动攻击
NPC 主动攻击
任务冲突
野外遭遇
地牢遭遇
阵营敌对
事件触发
犯罪行为
护送或防守失败
```

战斗结果可能影响：

```text
角色死亡
角色受伤
昏迷
被俘
逃跑
物品获得或损失
关系变化
犯罪 / 通缉
声望变化
任务变化
场景状态
势力关系
```

### 9.4 成长系统

角色成长是核心系统。

成长维度包括：

```text
等级
技能
属性
装备
关系
知识
```

其中等级、技能、属性最重要。

成长应影响玩家能做什么、战斗能力、制作能力、经营效率、社交结果和探索范围。

### 9.5 物品与交易系统

物品类型包括：

```text
装备
消耗品
关键道具
材料
商品
任务物品
经营物资
种植物
动物产物
炼金产物
```

交易内容包括：

```text
商店购买
商店出售
订单
委托
议价
地区价格差异
经营库存
```

### 9.6 种植、制作、经营系统

经营玩法不是轻量附属系统，而是可独立游玩的路线。

三大方向：

```text
种植：
种田、养动物、采集、农产品加工。

制作：
工坊、装备制作、炼金、材料加工。

经营：
旅馆、商店、公会、据点、领地。
```

玩家可以完全不参与，也可以把其中某条路线作为主要玩法。

### 9.7 时间与世界变化

世界存在时间。

基础时间结构包括：

```text
白天
夜晚
日期
季节或阶段
事件周期
NPC 日程
商店营业时间
作物成长时间
任务时限
```

世界状态主要通过玩家操作改变，也可以通过时间、NPC 行动和世界事件发生变化。

### 9.8 结局系统

游戏没有固定结局。

玩家死亡时可以：

```text
回档
进入结局结算
```

玩家也可以主动选择结束旅程，并根据经历生成结局。

结局应参考：

```text
玩家身份
探索经历
完成任务
战斗结果
经营成果
重要关系
阵营立场
声望
财富
死亡或退隐方式
世界状态变化
```


表现层的目标是让玩家感到自己在一个真实运转的 RPG 世界中行走。

主要规则系统：

## 12. AI 边界

AI 可以增强 RPG，但不应替代 RPG 规则。

AI 适合：

```text
生成 NPC 对白
生成 NPC 临时反应
生成任务候选
生成地点描述
生成传闻
生成程序区域的语义背景
总结玩家经历
辅助形成 NPC 记忆和印象
为结局生成叙事结算
```

AI 不应直接：

```text
决定战斗胜负
直接发放物品
直接修改等级
直接完成任务
直接改写地图事实
直接生成不可校验的奖励
直接决定 NPC 是否死亡
```

基本关系：

```text
游戏规则决定事实。
世界状态保存事实。
游戏表现展示事实。
AI 生成表达、解释、候选内容、摘要和叙事反馈。
```
