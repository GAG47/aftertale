# Aftertale 地图生成架构

## 文档目的

本文定义 Aftertale 地图系统的长期架构，不描述某个开发版本的完成情况，也不以当前代码实现反推设计。

地图生成采用“语义编译”思路：

```text
World Frame
  ↓
Region Layer
  ↓
Location Graph
  ↓
Location Scene
```

四层分别回答不同尺度的问题：

```text
World Frame：世界的大尺度背景是什么？
Region Layer：这个背景中成立了哪些区域事实？
Location Graph：玩家能够前往哪些逻辑地点，地点之间如何通行？
Location Scene：一个逻辑地点进入后具体是什么可玩空间？
```

核心原则是：

> 先生成语义结构，再生成空间表现；不能从 TileMap 反推世界结构。

---

## 一、总原则

### 1. 分层权威

每一层只决定自己尺度内的事实：

```text
World Frame 约束 Region 的大背景。
Region Layer 决定区域尺度事实和局部语义角色。
Location Graph 决定逻辑地点和地点间的通行关系。
Location Scene 实现单个地点的具体可玩空间。
```

下层不得反向改写上层：

```text
Scene 不能自行创造 Location 或 Region。
Location Graph 不能改写 World 的大地形和大政治格局。
Region 不能违背 World 提供的粗尺度背景。
World 不能提前吞掉 Region、Location 或 Scene 的细节责任。
```

当下层发现上层信息不足或冲突时，必须让对应上层重新规划或明确失败，不能在下层静默补造结构。

### 2. 结构与表现分离

Location 是逻辑地点，Scene 是空间实现。两者不能混为一体。

Location 可以作为：

```text
旅行目标
任务目标
NPC 日程目标
独立状态单元
```

Scene 内部结构负责：

```text
道路、建筑、房间和地形
碰撞、物件和交互点
NPC 的具体站位
入口、出口和出生坐标
```

如果一个空间需要独立旅行、独立任务定位、独立日程定位或独立保存状态，它应当升格为 Location；否则应留在所属 Scene 内部。

### 3. 节点与边

Location Node 是旅行与运行时世界逻辑的基本地点单位。

Region 为节点生成提供局部背景、规划空间和来源归属，但 Region 不是通行边的端点。Location Graph 的边始终连接 Location Node。

边只表达地点之间的通行关系及必要通行约束，不表达：

```text
包含关系
生成关系
父子场景关系
区域归属关系
```

例如：

```text
橡木镇中心 ↔ 农田
```

只表示两个地点可以互相前往。农田属于哪个 Region，由节点来源或区域归属表达，不由这条边表达。

跨区域通行同样只是两个真实 Location Node 之间的边。不能为了表示“以后可能连接”而制造没有独立地点意义的占位节点。

### 4. 分阶段编译

地图不是运行时边走边临时推理出来的。每一层应产生可校验、可固化的独立产物：

```text
上层事实或规则
  ↓
编译为本层结果
  ↓
校验
  ↓
固化
  ↓
供下一层或运行时读取
```

生成阶段负责创造世界结构；运行阶段只消费已经确定的结构。运行时不得重新解释 Region、重建 Location Graph，或把场景偶然结果写回上层结构。

## 二、World Frame：粗尺度世界底板

### 1. 职责

World Frame 只描述世界尺度内容：

```text
大陆与海洋
大型山脉、平原和森林带
世界级河流和水体
国家的大致范围
少数核心城市
世界级固定地标
边境、内陆、海岸等粗关系
```

World Frame 不负责：

```text
普通村镇和普通森林
区域剧情、危险度和魔法影响
区域内部道路和地点
区域内部势力分布
普通区域之间的具体通行
```

World Frame 不是“装下所有 Region 的容器”，而是下层可以查询的粗尺度语义背景。

### 2. 表达方式

World Frame 不应实现为高精度 TileMap。适合的基础表达是：

```text
polygon / mask：大陆、国家、大型地貌带
polyline：世界级河流、大型路线
anchor：王都、世界树、世界级遗迹
```

这些数据可以烘焙为低精度语义采样表。

### 3. 查询接口的语义

给定世界坐标，World Frame 返回大尺度语义或权重，例如：

```text
所在国家
主要大型地貌
附近大型地貌
到大型水体的距离
到核心城市或世界地标的距离
边境、内陆或海岸关系
```

它不返回：

```text
具体村镇名称
命名森林区域
区域魔法影响
区域危险度
局部道路
```

一句话定义：

> World Frame 是粗语义查询器，不是 Region 生成器。

### 4. 产物

World 层产物应包含：

```text
稳定的粗尺度语义源数据
可重复的空间查询结果
参与查询的世界级形状、路线和锚点
```

它不包含 Region、Location Node、通行边或 Scene 布局。

---

## 三、Region Layer：区域成立与局部规划

### 1. 职责

Region Layer 在 World Frame 提供的背景中建立区域尺度事实。它回答：

```text
这里是否成立一个区域？
区域叫什么、是什么类型？
区域处于什么粗尺度地理背景？
区域具有哪些局部自然、社会或特殊影响？
区域应当产生哪些语义功能？
这些语义功能适合落在局部空间的什么位置？
```

Region 可以决定 World 不需要预先知道的局部事实，例如：

```text
溪流、小丘和林缘
农田外围和牧场
区域道路倾向
古树、遗迹和隐居点
局部魔法影响区
资源倾向和危险边缘
```

同一种地理概念可以出现在不同尺度。世界级大河属于 World，区域溪流属于 Region，场景水渠属于 Scene，三者并不冲突。

### 2. 输入

Region 的主要输入是：

```text
区域锚点
World 粗语义查询结果
Region 类型和生成规则
确定性的生成参数
```

Region 不需要读取完整世界高精度地图。

### 3. 局部语义场

Region 应建立自己的局部坐标系，并在其中生成 feature maps。可用语义场包括：

```text
可建造度
坡度
水系
道路倾向
林地密度
中心性
边界方向
资源倾向
特殊影响区
占用或 claim map
```

World 只提供初始条件，Region 在这些条件下生成局部事实。

### 4. 语义角色规划

Region 不直接随意制造 Location Node，而是先确定区域需要哪些语义角色：

```text
生活核心
农业外围
主要通路
特殊地标
危险边缘
隐居点
资源点
```

每个角色根据 feature maps 计算适配度，选择高分位置，并在 claim map 中登记占用。后续角色可以避让、依附或约束已有角色。

示例：

```text
生活核心：
高可建造度 + 高中心性 + 接近道路倾向

农业外围：
平坦 + 靠近水 + 靠近生活核心

森林入口：
靠近区域边缘 + 接近森林方向

隐居小屋：
低中心性 + 高林地密度 + 远离主路
```

语义角色表达的是一个真实地点应承担的功能，不是为了未来接边而存在的占位意图。

### 5. 产物

Region Result 应包含：

```text
区域身份与类型
World 背景采样
区域尺度事实
局部坐标与必要语义场结果
已经确定的语义角色及其来源
生成 Location Graph 所需的约束
```

它不包含 TileMap、碰撞、出口坐标或场景物件。

---

## 四、Location Graph：逻辑地点与通行拓扑

### 1. 职责

Location Graph 决定：

```text
世界中有哪些可进入的逻辑地点
地点之间是否能够通行
通行是否有方向或条件
哪些地点能作为旅行、任务和日程目标
哪些地点需要独立保存状态
不同 Region 产生的真实地点如何接通
```

Location Graph 是语义结构，不是 TileMap，也不能从 TileMap 反推。

### 2. 节点生成

Location Node 由已确定的语义角色展开：

```text
语义角色
  ↓
Location 类型与身份
  ↓
Location Node
```

例如：

```text
生活核心 → 橡木镇中心
农业外围 → 农田
特殊地标 → 古树空地
主要通路 → 镇东小路
隐居点 → 魔女小屋
```

每个节点都必须：

```text
有独立地点意义
有稳定身份
能追溯到来源角色和生成规则
具备明确的 Location 类型
不依赖未来可能存在的边证明自身合理性
```

### 3. 边生成

边根据节点语义和图规则生成，而不是随机把节点连成图。

区域类型可以提供图 grammar，例如：

```text
小镇：
核心连接农业外围和主要通路。
核心可以连接地标。
隐藏危险地点不直接连接生活核心。

森林：
入口连接普通林地。
普通林地连接空地。
空地可以连接隐居点或深林。
隐藏地点不能成为默认主路径节点。
```

不同 Region 来源的节点不需要先被抽象成“区域外部连接”。当两个真实地点满足通行规则时，图直接建立节点到节点的边：

```text
镇东小路 ↔ 森林入口
```

两个端点的 Region 来源可以用于解释或校验关系，但不能改变“边连接节点”的基本事实。

### 4. 图约束

Location Graph 的约束应由明确规则声明，而不是由下游补救。典型约束包括：

```text
必需节点存在
节点和边身份唯一
所有边端点存在
任务和 NPC 使用的地点满足可达性要求
入口数量符合区域类型
隐藏地点没有误接主路径
图深度与区域规模相符
需要接通的地点关系已经形成真实边
```

是否要求整张图完全连通，应由该图的正式约束决定，不能由 Snapshot 或 Scene 阶段擅自追加。

### 5. 产物

Location Graph Result 应固化：

```text
Location Node 集合
节点来源
通行边集合
方向和通行约束
图级约束
规则与输入来源
稳定身份和完整性信息
```

它不包含：

```text
TileMap
场景坐标
出口坐标
玩家出生点
NPC 具体站位
运行时当前位置
玩家状态
```

## 五、Location Scene：单个地点的空间编译

### 1. 职责

Location Scene 把一个 Location Node 实现为具体可玩空间：

```text
TileMap 和地形
道路与路径
建筑与内部局部结构
树木、物件和装饰
碰撞
交互点
NPC 站位
入口、出口和出生坐标
```

Scene 不决定世界中是否存在该地点，也不能创造 Location Graph 中没有的旅行出口。

### 2. 类型分派

不同 Location 类型应使用不同的空间生成策略：

```text
town_center：
道路骨架 + 广场 + 建筑地块 + 地标

farmland：
田间路径 + 田块 + 水渠 + 农舍

forest_entrance：
林间主径 + 边缘林地 + 树墙

forest_clearing：
空地中心 + 植被密度场 + 采集点

witch_hut：
小径 + 固定小屋模块 + 周边林地

capital_district：
街道骨架 + 街区地块 + 建筑密度
```

不能用一种统一布局算法生成所有地点。

### 3. 生成顺序

Scene 应先满足图结构，再填充视觉内容：

```text
读取 Location Node 及其通行边
  ↓
放置对应入口和出口
  ↓
生成主路径骨架
  ↓
放置核心结构
  ↓
填充地形、建筑、物件和装饰
  ↓
执行寻路与可达性校验
```

核心规则：

```text
Graph 声明的每条场景通行关系必须有对应出口。
Scene 不能生成 Graph 中不存在的旅行出口。
出口的目标语义必须与 Graph 一致。
```

### 4. 聚落类场景

小镇、村庄和城区适合使用 feature maps 与迭代规划器，而不是把 BSP 作为主要逻辑：

```text
feature maps
  ↓
道路种子
  ↓
道路规划器扩展
  ↓
建筑、农田、广场和地标规划器竞争选址
  ↓
claim map 防止重叠
  ↓
道路可达性校验
```

这里的 agent 是生成规划器，不是游戏中的 NPC。每个规划器只负责：

```text
提出候选位置
计算候选分数
成功后登记占用
```

### 5. 自然类场景

森林、平原、溪边和山脚适合使用路径骨架与密度场：

```text
基础地貌场
  ↓
路径骨架
  ↓
植被或障碍密度场
  ↓
空地、资源点和局部结构采样
  ↓
出口可达性校验
```

自然场景不是随机散布地物。路径、边界、空地和密度变化共同构成可读的空间结构。

### 6. 产物

Scene Result 应包含：

```text
可重复构建或已经固化的空间布局
入口、出口与 Graph 边的对应关系
地形、碰撞和对象放置
玩家与 NPC 的有效站位
场景生成规则、seed 或完整快照
```

它不得反向修改 Region Result 或 Location Graph Result。

---

## 六、统一校验与失败归属

每一层必须校验自己的产物。下层校验不能代替上层校验。

### 1. Region 校验

```text
是否违背 World 粗语义
必需语义角色是否存在
角色位置与距离是否合理
局部事实是否互相冲突
角色是否落在适合的语义场位置
```

### 2. Location Graph 校验

```text
节点和边引用是否合法
必需地点是否存在
正式声明的可达性约束是否满足
任务与 NPC 使用的地点是否可达
隐藏地点是否误接主路径
不同来源节点之间的边是否连接真实端点
```

### 3. Scene 校验

```text
出口是否与 Graph 边一一对应
出口目标是否正确
出生点到必要出口是否可达
关键交互物是否可达
NPC 站位是否有效
碰撞是否堵死主路径
```

### 4. 失败处理

失败必须回到拥有该事实的阶段：

```text
Scene 出口或寻路失败
  → 重试或拒绝该 Scene 结果

Location Graph 缺少必要节点或边
  → 回到 Location Graph 规划

Region 角色无法成立
  → 回到 Region 局部规划

Region 与 World 背景冲突
  → 更换 Region 锚点或拒绝该 Region
```

任何下层都不能通过增加上层事实来“修好”自己的失败。

---

## 七、编译产物与运行时边界

### 1. 独立产物

地图管线至少应区分：

```text
World Source
  粗尺度世界底板

Region Result
  已确定的区域事实和语义角色

Location Graph Result
  已确定的地点节点和通行边

Scene Result
  已确定的可玩空间
```

各产物必须能追溯输入、规则和稳定身份。固化阶段只保存并复验上游结构，不能新增、删除或修补地图内容。

### 2. 运行时职责

运行时只做：

```text
读取已经固化的 Location Graph
  ↓
确定当前 Location
  ↓
加载或按已固化参数重建对应 Scene
  ↓
通过 Scene 中映射到 Graph 边的出口切换 Location
```

运行时状态包括当前位置、访问记录和玩家状态。这些状态属于会话或存档，不属于静态地图结构，也不能写回 Location Graph Snapshot。

---

## 八、固化与保存策略

建议采用 `snapshot + seed + diff` 的组合：

```text
结构层：保存 snapshot
可重建的表现层：保存 seed 或完整 Scene Snapshot
运行后变化：保存 diff
```

建议边界：

```text
World Frame：
保存稳定源数据或烘焙结果。

Region：
保存已经成立的区域结果。

Location Graph：
保存节点、边、来源和约束的结构快照。

Location Scene：
可保存生成 seed、生成参数或完整布局快照。

运行时变化：
保存相对固化场景的状态差异。
```

以下变化不能只靠 seed 重建：

```text
树被砍伐
箱子被打开
门被解锁
NPC 迁移
作物成长
任务改变场景状态
```

这些属于运行时差异，不应污染静态地图生成产物。

## 九、完整示例：橡木镇与微光森林

### 1. World Frame

```text
xx 王国位于东大陆中部。
王国中央有王都。
王国东部是大型平原。
王国东境外有大型森林带。
王国南部有世界级大河。
```

World 到此停止，不命名橡木镇、微光森林、魔法影响或局部道路。

### 2. Region Layer

橡木镇在东部平原背景中成立：

```text
农业小镇
农业外围
靠近东境森林带
具有通向森林方向的真实通路需求
```

微光森林在大型森林带背景中成立：

```text
命名森林区域
普通林地与深林
古老魔法影响区
空地和隐居点
```

这些都是 Region 事实，不是 World 事实。

### 3. Location Graph

语义角色展开为真实地点：

```text
橡木镇中心
农田
古树空地
镇东小路

森林入口
林中空地
魔女小屋
深林
```

通行关系：

```text
橡木镇中心 ↔ 农田
橡木镇中心 ↔ 古树空地
橡木镇中心 ↔ 镇东小路

镇东小路 ↔ 森林入口

森林入口 ↔ 林中空地
林中空地 ↔ 魔女小屋
林中空地 ↔ 深林
```

`镇东小路 ↔ 森林入口` 是两个 Location Node 的普通通行边。它不表示包含关系，也不需要一个额外的“区域边界占位节点”。

### 4. Location Scene

橡木镇中心 Scene 可以实现：

```text
村道、广场、民居、商店和水井
NPC 站位
通往农田、古树空地和镇东小路的出口
```

农田 Scene 可以实现：

```text
田块、作物、农舍和水渠
通往橡木镇中心的出口
```

森林入口 Scene 可以实现：

```text
森林边缘、树墙和林间小径
通往镇东小路和林中空地的出口
```

魔女小屋 Scene 可以实现：

```text
林中空地、小屋外观、室内局部空间和草药物件
魔女 NPC 站位
通往林中空地的出口
```

如果小屋室内以后需要独立旅行、任务定位、日程定位或状态保存，它应由上层重新规划为 Location；Scene 不能自行把房间升级成节点。

## 十、长期架构约束

以下约束是地图系统的长期判断标准：

```text
1. World 只提供粗尺度背景，不生成 Region 细节。
2. Region 生成局部事实和语义角色，不生成具体 TileMap。
3. Location Node 是旅行和世界逻辑的基本地点单位。
4. Region 是节点生成上下文与来源，不是通行边端点。
5. 边只连接真实 Location Node，不连接占位意图。
6. Location Graph 先于 Scene，不能从 Scene 反推。
7. Scene 必须实现 Graph 已声明的出口，不能创造新出口。
8. 每层拥有独立产物、校验器和明确失败边界。
9. 下层失败不能通过篡改上层结构静默修补。
10. 生成阶段创造并固化结构，运行阶段只消费结构。
11. 静态地图、场景重建参数和运行时状态必须分离保存。
12. 所有生成结果都应可追溯、可复验、可确定性重建。
```

最终架构可概括为：

```text
用低精度 World 语义采样提供背景；
用 Region 局部语义场建立区域事实和角色；
用语义角色展开 Location Node；
用图规则连接真实地点；
用 Location 类型分派生成具体 Scene；
用逐层校验阻止结构错误下沉；
用 snapshot 固化结构，用 seed 和 diff 管理空间与状态。
```
